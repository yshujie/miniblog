# miniblog 管理端设计说明

> 本文为已接受的管理端设计基准；应用实现及 2026-10-09 验收结果见 [admin-ui-refactor-verification.md](admin-ui-refactor-verification.md)。

本文把管理端整理为个人技术博客作者的日常工作台。四个主要入口是 **工作概览、Notion 自动同步、目录与收录、文章库**；已认可的两个内容工作台菜单保留。账户信息进入头像菜单，目录维护进入所选目录的上下文。

这是基于当前代码与契约的设计方案，不代表应用已实现、部署或生产验收。交互原型中的文章、时间、计数与状态均为演示数据；真实实现必须以接口返回为准，未读取的值不能显示为零或正常。正文继续在 Notion / 飞书等外部文档维护，管理端不增加原生正文编辑器。

## 1. 作者任务与设计边界

| 作者要完成的任务 | 默认入口 | 完成后可确认的结果 |
| --- | --- | --- |
| 查看外部文档的变更是否同步，以及哪些情况需要核对 | 工作概览 → Notion 自动同步 | 看到扫描时间、来源状态、运行结果和实际公开条件 |
| 整理知识主题、章节、子章节与阅读顺序 | 目录与收录 | 目录归属、启用状态和顺序由确认后的响应更新 |
| 收录未托管的 Notion / 飞书链接，连续补充文章 | 目录与收录或文章库 → 收录面板 | 明确新建或已收录，不重复创建或覆盖现有文章 |
| 查找文章、检查发布结果、维护本地作者信息 | 文章库 → 文章详情 | 区分来源管理与本站资料，看到允许执行的操作 |
| 暂时阻止本站阅读，随后重新核验 | 文章详情 → 紧急下架面板 | 本地下架标记独立于来源发布状态，解除不等于立即公开 |

不增加新收录的“保存草稿”、批量操作、全库文章来源筛选、PV / 增长图表、用户或 RBAC 管理、服务总开关编辑、重试旧运行、重放旧预览、网页历史接管。已有手工草稿、归档恢复和单篇状态操作继续按当前接口与允许动作执行。

保留既有目录层级、code、文章字符串 ID、查询参数和兼容路由。改显示名称或菜单归属不意味着改数据库身份、API 参数、公开链接或层级规则。后端 API 不变。

## 2. 完整菜单树与兼容入口

```text
miniblog · 作者工作台
├─ 工作概览                         /home
├─ 内容工作台
│  ├─ Notion 自动同步               /content/sync
│  │  ├─ 概览                      页面内 tab
│  │  ├─ 来源与绑定                页面内 tab
│  │  ├─ 页面状态                  页面内 tab
│  │  └─ 运行记录                  页面内 tab
│  └─ 目录与收录                   /content/workbench
│     ├─ 所选主题 / 章节 / 子章节详情
│     ├─ 上下文中的新增、编辑、启停、删除与顺序调整
│     └─ 收录外部文章面板
└─ 文章库                          /article/list
   └─ 文章详情                     /article/edit/:id

头像菜单
├─ 我的信息：昵称、角色、简介（只读）
└─ 退出登录

兼容入口（不再占用常驻主导航）
├─ 模块维护                        /module/list
├─ 章节维护                        /section/list
├─ 子章节维护                      /subsection/list
├─ 收录入口                        /article/create
├─ 登录                            /login
└─ 404                             /404（无权限另按现有状态处理）
```

模块在面向作者的目录界面可显示为“主题”；数据和请求仍使用 `module_code`。既有三个目录 CRUD 页面继续可用，与新的目录上下文调用相同能力，不先删除兼容路径。

`module_code`、`section_code`、`subsection_code`、`collect=1` 等既有收录上下文继续有效；`/article/create` 仍承接旧入口并打开同一收录能力。保持现有 hash 路由和登录返回路径行为，不借 UI 改造切换路由模式。页面内 tab 如增加地址状态，应保留原 query 并安全回退未知值，不新增后端契约。

常驻头部提供页面位置、移动导航按钮与博客入口；头像入口放在导航底部，打开只读账户资料面板。去掉模板项目 / 文档链接、页面标签栏、组件尺寸、全屏、开发错误工具和浮动外观设置。历史错误仍由页面展示，开发诊断能力不混入作者任务。

## 3. 六个关键画面与页面职责

六个画面覆盖五个页面及同步页的一个关键 tab，不增加六个独立路由。

### 3.1 工作概览

回答“现在是否需要处理内容，下一步去哪里”。顶部用简短任务说明与当前工作入口，避免欢迎卡、账户介绍和操作教程占据首屏。

- 同步摘要：健康状态、最近完整扫描、最近成功、正在运行的任务。时间缺失显示“暂无记录”；读取失败显示“暂未读取”，不能保持假成功。
- 需要核对：历史待核对、公开受限、读取 / 执行失败三个实际指标，使用 `SyncStatus` 返回值。不把普通草稿、停用来源或等待历史核对统一渲染为故障。
- 工作入口：收录文章、继续整理目录、查看同步结果。最近目录仅使用已有本机记录，并标明“最近使用目录”；不伪造云端操作历史或最近更新时间。
- 若展示运行摘要，取已有运行接口结果，不生成虚构活动流。文章总量只有在相应全量查询返回 `total` 后才能展示，不能拿当前页行数当全站总量。

主动作是“收录文章”，受现有收录开关控制；次动作是“查看同步状态”“整理目录”。首页不直接放来源配置、维护暂停、公开影响操作或大量筛选器。

### 3.2 Notion 自动同步：概览

保留“Notion 自动同步”名称，四个 tab 放在标题与简短说明下。概览集中显示当前同步结果和动作，不再把四类长表纵向叠在一屏。

默认突出“运行预览”，明确预览只读取并记录结果，不修改文章或目录。“手动同步”是独立写动作，按所有现有门槛启用，并保留执行确认。两者不能通过一个含糊的“同步”按钮合并。

“刷新状态”为次要动作；维护暂停、解除暂停、来源回填暂停进入清晰的维护操作区，不与日常按钮同等强调。服务总开关只显示配置事实；网页不能开启 `enabled`。来源停用、维护暂停和本地紧急下架使用不同名称与说明。来源回填暂停还会阻止手工收录、手工资料编辑、移动和普通状态变更；服务拒绝时显示具体原因并保留输入。

手动同步禁用时展示具体原因：总开关关闭、维护暂停、来源回填暂停、历史基线未冻结、当前运行尚未完成等。状态未读取完成时也不能假定可执行。新运行发出后显示确认的 `run_id`；明细读取失败只重读详情，不再次创建运行。

### 3.3 Notion 自动同步：来源与绑定

每个来源展示名称、所属主题、启用状态、健康和最近扫描结果。内部 `source_id`、property ID、option ID 保留在详情或配置面板，不成为列表的主要文案。

绑定表围绕“Notion 主题 → 本站章节 → 状态 / 原因 → 调整绑定”。主动作是具体冲突的“调整绑定”；来源配置为次动作。绑定只能选择同模块正常章节，不能自由跨主题绑定。

来源配置、绑定调整使用侧面板；桌面允许并排看编辑时资料、当前草稿、最新资料。版本冲突不能自动提高 revision 重试，也不能用读取最新版覆盖草稿。用户显式核对并采用最新版本作为保存依据后，再按最新 revision 提交变化字段。

修改名称、启停与修改模块 / 字段映射的影响不同。可能要求托管文章重新核验的修改保留公开影响提示和确认；不修改现有后端规则。历史接管资料只能展示只读对照及维护说明，没有网页接管或回填按钮。

### 3.4 目录与收录

目录树用于选择上下文；右侧内容包含完整目录路径、目录详情和该位置的文章列表。所选位置随页面内切换保持，打开面板后不丢失筛选或待提交资料。

目录详情承接主题 / 章节 / 子章节的新增、标题编辑、启停、删除与同级顺序调整。兼容 CRUD 页面可从上下文次要入口到达；不要再要求作者在三个主菜单中来回寻找同一目录。

目录状态只在明确值下显示：当前约定 `1` 为正常、`2` 为未上架；未知或缺失值显示“状态待确认”，不能当作已启用。标题修改保留原 code；目录重排只针对同级完整顺序，不移动层级或归属。删除遵循现有接口依赖校验，不自动级联、迁移或清理子项。

文章列表与文章库复用查询、详情、收录和允许操作。这里负责所选目录的归属、顺序与连续收录，文章库负责跨目录查找。

排序仅在有效章节直属位置或子章节内、标题与状态筛选已清空时可用；包含子章节的聚合列表不能排序。请求基于该位置完整的未归档文章顺序，不能仅重排当前分页。保留上移 / 下移，不在本轮增加拖拽或批量提交。

主动作“收录文章”；目录编辑、刷新和文章移动为次动作；启停 / 删除放到明确对象的上下文菜单并保留现有确认。文章行显示全标题，来源与状态以轻量徽标提示，低频操作收进“更多”。

### 3.5 文章库

全站查询保留标题、本站状态、目录与分页；筛选使用现有 API，不增加无法作用于全库的“Notion / 手工”筛选。来源管理方式作为每行徽标展示。

桌面优先列为标题、目录、本站状态、实际公开、操作。作者、标签可在宽屏作为次要列，在窄屏进入详情。操作区域只显示最常用的查看 / 编辑，其余按 `allowed_actions` 收进菜单，避免固定 390 px 的操作列占据正文列表。

“本站已发布”与“前台可见”分开。`effective_visibility` 仅在明确 `true` / `false` 时显示结果；缺失显示“尚未提供”。文章 DTO 没有来源期望和可见性原因时，不从状态或链接推导，提供适用的“查看同步状态”入口。

主动作“收录文章”；查询、清除条件和刷新为次动作。查询结果数量来自当前查询的 `total`，明确是筛选结果，不被标为文章库总量。

### 3.6 文章详情：托管与手工两种变体

标题、目录路径、来源徽标与当前状态先展示为清晰资料，避免将整页禁用表单当成只读展示。

| 内容或动作 | Notion 托管 | 手工文章 |
| --- | --- | --- |
| 标题、目录、标签、来源地址 | 只读，指明在来源维护 | 沿用当前资料编辑能力；原文地址保持现有只读行为 |
| 本地作者 | 允许动作包含本地编辑时可保存 | 允许编辑时随资料保存 |
| 正文 | 继续从外部文档阅读；历史正文只读折叠 | 继续在外部维护；已有历史正文只读折叠 |
| 发布、下架、归档、恢复 | 由来源管理，不显示本地覆盖操作 | 根据现有允许动作、四态与确认规则执行 |
| 移动目录 | 不替代来源分类 | 允许动作与有效目录条件满足时执行 |
| 文章排序 | 在有效目录工作台调整 | 在有效目录工作台调整 |
| 紧急下架 / 解除 | 仅按允许动作执行；与来源状态独立 | 不根据身份猜测支持能力，以允许动作返回为准 |

托管主动作“保存本地信息”，手工主动作“保存资料”。打开原文、重新读取、返回列表为次动作。下架等影响公开的动作明确说明范围，紧急下架使用独立面板：只阻止本站阅读，不撤回外部文档权限；解除后等待来源重新核验，不宣称立即可见。

保存失败保留输入，未保存时离开保留现有提示。手工编辑期间发生接管，保留旧输入作为核对资料，不继续写托管字段。使用后端 `allowed_actions`；托管记录缺少允许动作时保守只读，不仅凭 `provider` 或外链判断所有权。

## 4. 同步四 tab、详情与共享面板

| 区域 | 主要资料 | 操作与设计约束 |
| --- | --- | --- |
| 概览 | `SyncStatus`、当前任务、来源摘要 | 预览 / 同步语义分开；禁用理由明确；维护与服务配置区别展示 |
| 来源与绑定 | 分页来源、字段映射、目录绑定、配置版本 | 配置 / 绑定面板；冲突保留草稿与旧版本，不自动采用最新值 |
| 页面状态 | 标题、来源、管理状态筛选；来源期望、本站状态、实际公开和原因 | 只执行明确提交的筛选；健康刷新不提交筛选草稿；分页保持 |
| 运行记录 | 运行 ID、模式、阶段、状态、时间及真实 counts | 打开运行详情；没有“重试这次运行”或“应用旧预览” |

运行详情抽屉显示模式、状态、阶段和逐项结果，前后资料按需展开，技术 ID 可复制但不压过标题与原因。预览页面明确只读，历史 `bootstrap_preview` 保留只读对照。详情读取失败时显示“重新读取”，不能因此重复 POST 任务。

切换 tab / 抽屉不重置配置草稿或已提交查询；轮询可见时刷新，隐藏时停止，恢复时合并请求，并保留当前页和未保存输入。刷新健康不能改变来源配置保存依据或把筛选草稿变成查询。异步过期结果不能替换当前所选来源、运行或文章。

### 共享收录面板

所有入口复用一个收录流程：有效目录 → 外部链接 → 标题建议或手填 → 可选作者 / 标签 → **发布 / 发布并继续**。

- 保留最近有效目录和作者；连续发布清空每篇链接、标题、标签，保留上下文。没有新增“存为草稿”。
- Notion 标题建议不覆盖用户已改标题；飞书或无法取得标题时允许手填。预览失败不清空链接、目录和资料。
- 收录开关关闭时，入口显示禁用及原因；目录读取失败或无有效位置时不能提交。
- 已收录返回明确已有文章、现态和位置，不覆盖标题、目录、作者或发布状态。只提供现有允许动作中的打开、移动、归档恢复等选项。
- 请求期间防重复提交；结果不确定时保留冻结内容和原幂等键，使用“原样重试 / 返回修改”现有语义，不默认为失败并创建新文章。
- 提交成功以真实响应更新列表；关闭未提交面板保留现有清空输入提示。

## 5. 状态语言与完整状态矩阵

同步页面的三层状态是核心契约，不能缩为单个“已发布”标签。

| 层次 | 字段与含义 | 展示方式 |
| --- | --- | --- |
| 来源期望 | `desired_state`：Notion 希望的草稿 / 发布 / 下架 / 归档 | 文本或中性徽标；空值为“未填写或无法识别” |
| 本站状态 | `local_state` 或文章 `status`：本站已记录的四态 | 使用明确四态文案；`local_state=null` 为“尚无本站文章”，缺失为“尚未提供” |
| 实际公开 | `effective_visibility` 与同步页 `visibility_reason` | true 为“前台可见”，false 为“前台不可见”，缺失为“尚未核验”；原因另行显示 |

`needs_revalidation` 单独标记“等待重新核验”；`publication_hold` 单独标记“本地紧急下架”。同步页保留最近失败与公开原因的区别；不能把近期错误覆盖成当前公开判断。后台核验的可见性也不等于匿名浏览器已读到外部正文。

| 状态 / 场景 | 视觉与文案 | 恢复与禁止事项 |
| --- | --- | --- |
| 初次读取 | 同尺寸骨架或局部加载；数值“—” | 不显示假 0、不显示成功、不闪入可执行按钮 |
| 首次空来源 / 空目录 / 空文章 | 区分“暂无来源”“暂无目录”“此目录暂无文章” | 给适用的配置说明、目录创建、收录入口；不把功能关闭当空数据 |
| 筛选无结果 | 保留筛选器与已提交条件，说明没有匹配项 | 清除筛选；不提示新建目录或更改同步配置 |
| 读取失败 | 错误紧贴对应区域；若有旧资料保留并标出更新失败 | 重新读取；不把旧资料标成刚更新 |
| 提交中 | 当前操作按钮 loading，阻止重复请求 | 不清空草稿、不关闭面板、不执行第二份命令 |
| 提交明确失败 | 可读原因，保留完整资料和上下文 | 修正或按现有契约重试；不静默改状态 |
| 结果不确定 | 说明尚未确认，不当作成功或可随意新建 | 收录保持冻结内容 / 幂等键；运行保持已确认 run ID |
| 功能或动作禁用 | 禁用控件旁提供实际原因，触屏也能读到 | 不仅靠 hover tooltip；不添加网页开服务总开关的替代按钮 |
| 未知状态 / 未提供字段 | 中性“状态待确认”“尚未核验”“—” | 不依据 Published、空错误、有效链接或缺失 status 推导健康 / 可见 |
| 配置 revision 冲突 | 编辑时 / 草稿 / 最新资料对照；草稿和 revision 保留 | 显式核对后采用保存依据；不自动 force、不自动提高版本 |
| 绑定不在最新来源中 | 明确提示该绑定已不存在 | 禁止采用或保存不存在的绑定，保留草稿供核对 |
| 公开影响确认被取消 | 回到原面板，输入保持 | 不发保存请求、不关闭草稿 |
| 不存在 / 无权限 | 区分文章不可用、目录不可用、无权限、登录失效 | 返回列表、重新读取或登录；不露出未获授权路由 |
| 未保存离开 | 现有离开确认，焦点和原输入可恢复 | 取消后继续编辑，不以 tab 切换自动提交 |

成功用深绿、中性信息用灰色；待核对 / 待核验用少量琥珀色，明确失败或紧急下架用红色。颜色之外保留状态文字，避免彩色仪表盘。辅助计数不是装饰 KPI，不合并三类同步计数为含义不清的“异常总数”。

## 7. 响应式与桌面 / 移动取舍

| 宽度 | 导航与布局 | 资料与操作 |
| --- | --- | --- |
| 1440 | 全局 224 px 侧栏，60 px 头部；工作台目录树与内容并列 | 完整表格、并排版本对照、侧面板；页边距 32 px |
| 1024 | 全局侧栏保留；工作台内部目录改为可切换面板，保留当前路径 | 删减作者 / 标签等次要列，主要状态与操作保留；页边距 24 px |
| 768 | 全局导航用 264 px 抽屉、内容单栏；目录也按需打开 | 列表保留适合宽度的紧凑表格，配置面板占主要内容宽度 |
| 390 | 全局导航 / 目录选择分开打开，不叠多个抽屉 | 卡片展示标题、位置、状态与更多；编辑 / 收录采用全屏面板，16 px 输入字号 |
| 320 | 同 390，压缩辅助间距，主按钮允许分行 | 正文与表单可纵向滚动，无页面横向溢出；44 px 点击区、长标题完整换行 |

原型实际断点：内部目录并列布局在 **≤1200 px** 收为面板；全局侧栏在 **≤780 px** 转为 264 px 抽屉；文章列表在 **≤600 px** 改为卡片。同步页面状态表也在 600 px 下变成带字段标签的卡片，来源绑定等复杂短表允许在局部表格容器内滚动，页面本身不横向溢出。最终以 1440 / 1024 / 768 / 390 / 320 的浏览器测量和截图校准。

移动端优先工作概览、同步结果读取、标题查询、简单收录、本地作者和紧急下架。配置、绑定、目录维护继续可用，但不成为手机首屏主操作；版本对照按项目纵向展开，保留全部值。功能取舍是信息优先级与布局变化，不是凭设备宽度绕过允许动作或擅自关闭已有能力。

全屏面板只保留一个标题与关闭按钮，底部动作使用安全区和至少 44 px 点击区；面板正文在剩余高度滚动。320 px 短屏不能让固定头部 / 底部遮住关键输入或确认说明。打开后焦点进入，Escape / 关闭后返回触发入口；切换断点、路由离开关闭导航面板，配置草稿按现有编辑生命周期处理。

## 8. 当前 API 映射与可实现范围

以下路径是现有前端调用的相对地址；内容请求使用 `VITE_API_ROOT + /admin`，认证请求使用 `VITE_API_ROOT`。默认 API 根包含 `/v1`，设计不硬编码生产域名或替换请求封装。

| 界面能力 | 现有接口 | 契约要点 |
| --- | --- | --- |
| 同步摘要 | `GET /notion-sync/status` | 服务开关、双暂停、基线、当前任务、扫描时间、三类计数与来源摘要 |
| 来源列表 / 配置 | `GET /notion-sync/sources`；`PATCH /notion-sync/sources/:source_id` | 分页；变化字段；`expected_config_revision` |
| 主题绑定 | `PUT /notion-sync/catalog-bindings/:binding_id` | 来源、option ID、section code、配置版本保持 |
| 同步页面状态 | `GET /notion-sync/pages` | title / source_id / management_state 等现有查询，三层状态与原因 |
| 运行 / 详情 / 明细 | `GET /notion-sync/runs`、`/:run_id`、`/:run_id/items` | 分页、准确字符串 ID、逐项前后资料 |
| 运行预览 / 手动同步 | `POST /notion-sync/runs` | 仅 `dry_run` / `sync`；新鲜扫描，不能重放旧预览 |
| 维护暂停 | `PATCH /notion-sync/control` | 仅 paused / source_writes_paused；不包含 enabled |
| 目录读取 / CRUD | 既有 `/modules`、`/sections`、`/subsections` GET / POST / PUT / DELETE 及 publish / unpublish | 保留原参数、code 和层级；不要按显示名猜 URL |
| 目录顺序 | `POST /catalog/reorder` | kind、parent_code、同级完整 codes |
| 文章查询 / 详情 | `GET /articles`、`GET /articles/:id` | title、status、目录、direct_only、page / limit；准确 ID、真实 total |
| 手工资料 / 本地作者 | `PUT /articles/:id`；`PATCH /articles/:id/local-fields` | 前者不发送新正文；托管只提交本地允许字段 |
| 手工四态 | `PUT /articles/:id/publish|unpublish|archive|restore` | 按允许动作、状态与确认规则执行 |
| 移动 / 文章顺序 | `PUT /articles/:id/move`；`PUT /articles/reorder` | 有效目标、完整未归档位置列表；不基于分页局部排序 |
| 紧急下架 | `PUT /articles/:id/publication-hold` | held / reason；解除后重新核验 |
| 标题建议 / 收录 | `POST /article-sources/preview`；`POST /articles/register` | 手填可用、原幂等键、created / already_registered、publish 保持 |
| 账户只读 / 退出 | `GET /users/myinfo`；`POST /auth/logout` | 沿用昵称 / 角色 / 简介与现有会话清理；不新增编辑或权限管理 |

`ArticleInfo` 只有本站状态及可选实际可见性；`SyncPage` 才提供来源期望、本站状态、原因等同步资料。不能为文章库从当前同步分页拼出假全量来源视图，不能把未读取的状态关联成已核验结果。文章与运行 ID 全程按字符串处理。

当前 API 足以完成导航、页面重组、四 tab、面板、共享收录、目录上下文 CRUD 和响应式展示，不需要本轮新增后端接口。

以下需求仅作未来单独确认的边界，不默认实施：全库文章来源筛选需要真实服务端过滤与分页契约；账户编辑 / 密码修改需要核对并明确接入契约；首页跨状态聚合若需要专用摘要，应明确查询成本与新增接口。不借此次设计增加批量命令、流量分析、服务监控、用户权限、运行重试或网页历史接管。
