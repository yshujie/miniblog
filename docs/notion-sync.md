# Notion 自动同步维护指南

在 Notion 中编写、选择主题和设置「博客状态」，miniblog 定时同步标题、标签、目录、状态及阅读地址。正文、作者、历史 ID 和本地排序保留。 同组同步只写托管字段，保留历史目录列的数据库原值；真实移动才更新归属与位置，状态撤回只更新状态。飞书与未接管 Notion 文章继续手工收录。同步默认关闭；程序发布与历史接管分别验收。

## 来源与目录

`source` 调用固定官方接口；`notionsync.Service` 保留入口，内部由 runtime 管生命周期、run_coordinator 管租约和运行记录、query/config 管查询与配置、scanner 管五库协调、bootstrap 管历史接管；`catalog` 维护主题绑定与目录准备事务；`article` 在单个事务中投影；`reading` 统一公开规则。启动入口负责任务取消与停机等待，Notion 故障不阻止博客启动。

新主题包括空主题可创建章节，code 由稳定身份生成，排序追加。同名既有章节只生成待绑定建议，经后台确认复用原 code。改名不改变 code、排序、启用状态；主题消失保留目录及绑定。IAM、Qlume、数据结构、算法需分别确认章节。默认一主题对应一章节；在模块锁内拒绝其他有效主题占用同章（409），历史异常绑定不能轮流改名。删除目录检查绑定依赖。

## 配置和运行

- MINIBLOG_NOTION_TOKEN：运行只读内部连接，仅服务端安全环境注入，并授权五库读取。禁止日志、浏览器、构建参数和仓库存储凭据。
- MINIBLOG_NOTION_SYNC_ENABLED：运行总开关，默认 false。后台暂停与来源启用独立控制。
- MINIBLOG_NOTION_SYNC_INTERVAL：默认 5m，最低 1m；整轮最多四分钟。
- MINIBLOG_NOTION_SYNC_AUTHOR：新文章本地默认作者，可空；已有作者保持原值。 受控 CLI 与定时器从唯一账号读取有效昵称（最多 128 个字符）；不将未定义的历史用户 status 值解释为管理员身份，多账号或空昵称时拒绝自动选择。

同步版本固定 2026-03-11，串行每秒最多一次请求，单次十秒、最多三次只读尝试。429/529 遵守 Retry-After；超过本轮时限保存冷却退出。标题预览保留原五秒超时及不重试行为。

定时和手动任务共用数据库租约：六十秒有效、十五秒续租，使用数据库时间和递增 epoch。文章事务复核租约、配置及绑定版本，HTTP 在事务外。暂停、停机或失效任务不能继续提交。

每库查询归档与非归档分区、全部状态及全部游标，严格验证列表、游标与 request_status。官方可选状态合法省略时允许继续；显式 incomplete、畸形状态或游标均标记不完整。每个分区按去重前结果计数，达到 10,000 保守阻止完整扫描；本轮不增加分窗扫描。先汇总五库再判断跨库移动，缺席绑定页单独获取。查询不完整禁止按缺席撤回。403、404、限流及网络失败记录问题，保留最近成功状态与内容。成功读取确认原生归档、垃圾箱、移出五库或撤销公开才隐藏。已托管页面成功确认跨库移入停用或 schema 已失效的目标时，使用独立隔离事务隐藏并待重新核验；保留最近成功内容、目录、原始链接与来源绑定，目标记入审计，不新建或移动文章。可靠的草稿/下架/归档意图仍应用，确认 public_url 为空清除旧地址；403/404/超时或目标 schema 读取失败不作该推断。目标修复后正常新鲜读取并迁移，ID 不变。同库关闭来源继续冻结结果。

## 四态与管理权

| Notion 状态 | 已接管文章 | 尚无文章 |
| --- | --- | --- |
| 草稿 | 草稿，停止公开，保留 ID | 保存来源记录 |
| 已发布 | 完整校验后更新并公开 | 校验后创建文章 |
| 已下架 | 停止公开，保留文章 | 保存来源记录 |
| 归档 | 保留文章及来源，可以恢复 | 保存来源记录 |

自动公开需要有效 HTTP(S) public_url、合法标题与标签、有效主题绑定、完整且启用目录、有效来源和无本地下架或待核验标记。成功读取 public_url 为空清除旧值，失败保留上次成功地址。实际匿名阅读及嵌入另行验收。

provider=notion 不代表接管，生效绑定才取得管理权。托管标题、分类、标签、来源、状态只读；历史正文保留只读。旧 PUT 只接受未实际改变的托管字段，变更原子拒绝。移动、状态和导入同样在业务层保护。作者通过 local-fields 保存，归档不可编辑；排序仍由后台维护。

紧急下架是本地独立标记，同步不会清除。解除后进入待重新核验，可靠扫描确认后才公开。暂停冻结当前结果，不自动下架或解除管理权。

## API 和页面

沿用认证、/v1 和 code/msg/payload；新增 ID 是字符串。列表默认 page=1、limit=20，limit 最大 100。

| 操作 | 接口 |
| --- | --- |
| 状态、来源、页面 | GET /v1/admin/notion-sync/status、sources、pages |
| 暂停、来源配置 | PATCH /v1/admin/notion-sync/control、sources/:source_id |
| 目录冲突 | PUT /v1/admin/notion-sync/catalog-bindings/:binding_id |
| 预览、同步 | POST /v1/admin/notion-sync/runs，dry_run 或 sync，202+run_id |
| 运行和明细 | GET /v1/admin/notion-sync/runs、runs/:run_id、runs/:run_id/items |
| 作者 | PATCH /v1/admin/articles/:id/local-fields |
| 本地下架 | PUT /v1/admin/articles/:id/publication-hold |

配置和绑定提交 expected_config_revision，陈旧配置返回冲突。后台只提交变化字段；相同配置不写库、不增加版本、不隐藏文章。名称与来源启停的实际变化不触发文章重新核验；模块或字段映射真实变化保留核验保护，界面提示公开影响。dry_run 保存审计和基线，不修改 Notion、文章或目录。sync 重新扫描当前状态，不重放旧预览。首轮状态回填只走独立 CLI。

后台 /content/sync 提供来源配置、任务和问题处理。历史接管匹配固化在运行条目的 `after.bootstrap_preview`，后台只读对照 Page ID、文章 ID、当前博客状态、Notion 状态、目录变化、公开条件及指纹；历史回填和接管只走 CLI。页面 DTO 增加 nullable `local_state`、`needs_revalidation`、`effective_visibility` 和 `visibility_reason`；使用公开阅读同一查询批量核验可见性。工作台摘要可见时每十五秒刷新，隐藏后停止，回前台合并刷新且保留未保存输入。工作台分别展示来源期望、本站状态及阻止原因，提供打开 Notion、本地作者与下架操作。

公开目录和详情共用可见性查询并输出 reading_url。前台优先使用该值，旧服务端回退 external_link；iframe 和原文入口共用有效地址。目录缓存六十秒，可见阅读页定时核验，隐藏后暂停，恢复合并刷新。标题、排序变化保持 iframe；文章或地址变化才重建。404 清除内容，网络失败保留最近成功内容。历史链接按当前归属定位并保留 query/hash。

## 迁移和首轮接管

先备份、核验真实 schema、迁移标记、部署版本和现有文章。此前 47 页仅为审计起点。

1. 完成 [内容维护指南](content-refactor.md) 的 000004、身份审计和 000005。冲突未解决时停止。
2. 部署当前完整程序前执行 000006，仅扩展 tags_json 和六张同步表，总开关保持关闭。CI 的 [只读结构检查](../scripts/content-preflight/README.md) 要求 clean version >= 6 与真实字段约束齐备；关闭同步不能代替迁移。启动不会自动建表。兼容版本必须认识 JSON、别名、管理权和 reading_url。
3. 暂停同步及来源写入，排空任务、后台提交与导入。无损标签回填：`go run ./scripts/audit-content -apply -backfill-tags -report /tmp/miniblog-tags-audit.json`。JSON 非 NULL 时权威，NULL 才读取旧 CSV；上限 64KiB，超限报错。兼容 CSV 仅在无损且容量允许时更新。
4. 创建专用运行只读与一次性回填内部连接。两个连接均授权五库及必要页面；不得在聊天中提交 token。先用 `schema_check` 核对五库实际官方身份、标题 title、博客状态 select 四选项、主题 select、知识点 multi_select 与 ID 映射，任何不一致停止切换、不自动重建字段。
5. 配置五源模块，来源仍停用。全部五库均需可读取，执行完整 dry_run；首个完整基线固定当时所有历史页为 baseline_pending。此前 47 页只作参考。基线后新页经过预览不能被变成历史待接管页，后续正常同步可自动登记。
6. `bootstrap_preview` 只读列出匹配、重复、博客与 Notion 状态、目录/子章节变化、公开条件与指纹。标题仅为线索；可信 Page ID 或本轮证明属于同一页的精确地址才用于匹配。历史文章按当前博客四态建议回填；Notion 非空不同的状态拒绝覆盖。未匹配页必须明确 `new_page` 和四态；不从空值推导发布。核对模块/目录启用后新增公开的历史文章。
7. 目录准备允许审核 reuse_map，核对 option ID/名称和目标章节旧名称/状态/排序，再原子建立绑定及改名；既有 code、排序、启用状态保持。普通冲突保存待处理报告；非法审核输入完整回滚，不能把 would_create 当作已完成绑定。依次 Go → DDD → 数据库 → 数据结构&算法 → 项目开发。仅当期库双暂停并排空，执行 `catalog_prepare`，处理绑定（含 IAM、Qlume、数据结构、算法）、启用已审核目录和该来源；其他库保留停用/待审核。准备或绑定实际变化后重新生成最终预览及确认清单；陈旧指纹拒绝。确认文件只包含当期来源页面，核验最终运行 completed 且无 failed/blocked；pending/frozen 正常。确认项明确 Page ID、文章 ID 或新页、四态、审核人及必要的 legacy alias。已发布历史文章必须事先满足 public_url 与有效启用目录条件。
8. 已发布接管在写 Notion 前、回读后提交本地前共用公开条件校验；不要求原状态已经发布或已经托管。公开条件不足时远端写入次数为零，草稿/下架/归档不受公开地址不足阻挡。`bootstrap_apply` 仅向一次性任务注入独立写凭据，完成跨表身份审计后执行。逐页待写入→请求→回读→本地接管；超时先回读。回读后 MySQL 复核配置、文章、归属、身份及指纹，两个系统不宣称原子提交。普通扫描冻结中断 journal 的原审核元数据；显式重新审核重新获取页面，并原子保存新快照和指纹，失败不替换。只重试重新核验通过的失败项；未接管历史页仍待审核，不覆盖其手工文章。
9. 身份升级保存不可变 legacy_source_key，登记/编辑/导入与已知页面、公开阅读地址同时检查主身份和别名。历史外链、正文、ID、code、作者和排序不重写，重复歧义不合并。每库接管会设置待核验，必须立即解除维护暂停并执行 CLI `--mode sync --enable-sync` 全量新鲜读取（常驻总开关关闭时后台 HTTP 会拒绝同步），核对运行和逐项可见性，恢复预期可见性后才启动定时试运行。
10. 基线冻结后每库创建明确标记的验收页，仅在 Notion 操作新增、标题、主题、标签、四态和撤销公开；跨库移动与故障恢复先使用验收页，不对历史文章注入故障。同步不修改 Notion 分享权限。公开需要博客状态已发布及有效 public_url；匿名可读与 iframe 能嵌入分别验收，拒绝嵌入时“打开原文”必须可用。
11. Go 先手动同步后至少观察三十分钟/三次完整扫描；其余每库至少十五分钟/两次完整扫描；五库联合至少三十分钟/三次完整扫描。故障或身份冲突停止扩大范围，保留已验证库的结果。完成桌面/小屏浏览器及用户常用手机、未登录 Notion 的实际试读。回填结束撤销写连接，清理临时凭据，常驻只读。

GitHub Actions 的 `Notion read operations (manual)` 提供 main 分支上的五库 `schema_check`、`dry_run` 和 `bootstrap_preview`；服务器受限报告、凭据传递、配置门槛与失败恢复见[只读维护入口](../scripts/notion-ops/README.md)。只读 Secret 仅部署时原子写入服务器 .env，未配置保留现值；独立 `Notion reviewed maintenance (manual)` 用私有审核文件 ID/摘要、实际镜像 SHA 和来源版本开放固定维护动作；文件路径由程序构造。只有一次性 bootstrap_apply 任务读取写 Secret，成功/失败/取消清理暂存和本任务拥有的容器，常驻服务不持写凭据。

CLI 参数和确认文件格式见 `go run ./scripts/notion-sync -h`。运行期只读；bootstrap 凭据仅在审核维护窗口注入。

## 回退与验证

先双暂停并撤销租约，确认当前任务、租约、HTTP 取消等待及维护容器排空，再关闭定时器并核验实际容器、健康和 HTTP 状态。未决回填须先按原审核或重新核对恢复，不能直接解除暂停或扩大范围。定时器开关由受控配置更新与后端重启生效；可以在总开关已开启但双暂停且排空时准备下一库。开启前核验即时同步的当前来源版本、镜像和读取凭据证据，保持双暂停后单独恢复。保留文章、绑定、JSON、别名和 schema。000006 down 只回退标记，不删除数据。禁止回到不认识托管规则的原始程序。恢复历史值须核对版本，防止覆盖后续修改。

记录保留九十天，绑定及未解决问题长期保留。健康展示最近尝试、完整扫描及成功应用；超过十五分钟未完整成功显示异常。`pending_count` 为历史待审核，`blocked_count` 为托管公开候选受限（含本地下架、待重新核验），`error_count` 为读取或执行失败，普通草稿不算公开受限。成功应用时间仅记录实际启用且正常核验的来源；其他库的历史待审核不阻止 Go 试运行指标，停用库不得被误标已应用。正常待审核和非发布来源记录计入运行 `pending`，停用来源计入 `frozen`，不造成 CLI 失败；真实发布阻止与读取/执行失败仍分别计 `blocked`/`failed` 并返回部分失败。任务条目仍完整保留待审核、冻结及逐页阻止结果，未解决历史核对记录不按九十天清理。

结果见 [同步验证记录](notion-sync-verification.md)。代码、本地 MySQL、浏览器夹具、真实 Notion/飞书阅读、使用验收和生产部署分别记录。


## 2026-10-09 已批准 Go 接管范围

冻结的 47 页历史基线保留；Go 当期清单严格限定原 38 页：14 个可信匹配保留历史文章 ID、按本地已发布回填；24 个明确新页回填草稿，只建立来源记录；其余 6 篇 Go 手工文章保持。五个旧章节按审核复用，`concurrency&sync` 仅改标题为“并发编程”，`test` 与未分类另建有效绑定。其他四库仍逐库审核，不自动套用 Go 批准。

最终预览指纹重新获取；仅配置版本、准备目录和审计时间变化不要求重复批准相同语义。页面身份、内容、状态、归属或公开条件实质变化时只重新审核受影响页。私有清单编译器验证完整最新运行及原批准集合，使用新指纹分草稿和已发布两批，拒绝新增、缺失、重复或未批准条目。

后台预览在定时总开关关闭时可用；同步另检查总开关、双暂停、冻结基线和当前任务。可见轮询暂停隐藏页请求，恢复只刷新已经提交的查询条件，保留筛选与配置草稿。409 后显式读取最新配置并对照，不自动提高版本重试。历史预览显示运行 ID、时间、指纹及只读提示。
